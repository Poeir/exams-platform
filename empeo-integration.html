1. ระบบนี้คืออะไร

Gofive Exams คือระบบแบบทดสอบสำหรับพนักงาน/ผู้สมัครงาน มีข้อสอบ 2 ชนิดอยู่ในระบบเดียวกัน (ในเอกสารนี้เรียกข้อสอบแต่ละชนิดว่า engine):

Engineคืออะไรผลลัพธ์ที่ได้
English ข้อสอบวัดระดับภาษาอังกฤษสไตล์ TOEIC มีตัวจับเวลา — มี 2 ชุด: ชุดเต็ม 50 ข้อ (Listening + Reading, 7 พาร์ท, 50 นาที) และชุดสั้น 20 ข้อ (Grammar + Reading, 15 นาที) คะแนนดิบ + ระดับ (ชุดเต็ม 5 band / ชุดสั้น 3 band) + คะแนนแยกรายทักษะ/รายพาร์ท
MBTI แบบประเมินบุคลิกภาพในบริบทการทำงาน (คำถามเชิงสถานการณ์ 14 ข้อ) MBTI code (เช่น ISTJ) + เปอร์เซ็นต์รายแกน + ระดับความมั่นใจ

Empeo คุยกับระบบนี้ผ่าน REST API ระหว่าง server กับ server เท่านั้น ไม่ต้องยุ่งกับหน้าเว็บข้อสอบ — หน้าเว็บมีไว้ให้พนักงานนั่งทำข้อสอบ ส่วนการสั่งเปิดสอบและการรับผลเกิดขึ้นระหว่าง backend ของทั้งสองฝั่ง

3. แนวคิดหลัก 3 ข้อ

3.1 Authentication — key เดียวใช้ทั้งสอง engine

ทุก endpoint ฝั่ง parent ใช้ header เดียวกัน:

X-API-Key: <PARENT_API_KEY>   // แยกตาม environment — ขอจากภูริ
  • key เดียวใช้ได้ทั้ง English และ MBTI engine
  • key เดียวกันนี้ใช้เป็น secret สำหรับ verify ลายเซ็น webhook ด้วย (หัวข้อ 7)
ห้ามเด็ดขาด: ห้ามนำ key ไปไว้ใน browser / mobile app / โค้ด frontend ใด ๆ — key ต้องอยู่ฝั่ง server ของ Empeo เท่านั้น

3.2 Identity — ระบุตัวพนักงานด้วยคู่ (sourceSystem, externalUserId)

ระบบข้อสอบไม่รู้จักบัญชีผู้ใช้ของ Empeo — มันจำพนักงานแต่ละคนจากค่า 2 ตัวนี้ ที่ Empeo ส่งมาตอนสั่งเปิดสอบ:

Fieldค่าที่ Empeo ควรส่ง
sourceSystem"empeo" (ค่าคงที่)
externalUserIdEmployee ID ในระบบ Empeo เช่น "emp-001"

ต้องส่งค่าเดิมเสมอ สำหรับพนักงานคนเดียวกัน ทั้งตอนสอบ English และ MBTI — ระบบจะรวมประวัติทุกการสอบของคน ๆ นั้นไว้ด้วยกัน และ Empeo สามารถดึงประวัติย้อนหลังด้วยคู่ค่านี้ได้ (email / displayName เป็น optional ใช้แสดงผลเฉย ๆ)

3.3 Naming convention เดียวกันทั้งสอง engine

ทุก field ที่ Empeo เห็น (request, response, webhook) เป็น camelCase และใช้ชื่อ field ชุดเดียวกันทั้งสอง engine — ฝั่ง Empeo จึงเขียนโครงสร้างรับข้อมูล (DTO) แค่ชุดเดียว ใช้อ่านผลได้ทั้งสองข้อสอบ:

ทั้งสอง engine
รูปแบบชื่อ fieldcamelCase (attemptId, externalUserId, callbackUrl, ...)
Status ตอนสอบเสร็จ"completed"
Field เวลาเสร็จcompletedAt
ลิงก์ทำข้อสอบlaunchUrl
View link{ attemptId, viewUrl, expiresAt }

ความต่างเดียวที่เหลือคือ base path: English /english/api/... · MBTI /mbti/api/v1/... และชื่อ endpoint (/sessions vs /assessment-attempts) — ดู section 5–6

4. Flow การทำงานหลัก

การสอบหนึ่งครั้งมี 3 ขั้นตอน — Empeo เขียนโค้ดแค่ขั้น 1 กับ 3:

Empeo Server → Exam Server
สร้างการสอบ (Create Session / Attempt)

HR กดสั่งสอบใน Empeo → backend ของ Empeo เรียก POST /english/api/sessions หรือ POST /mbti/api/v1/assessment-attempts พร้อมแนบ employee id และ callbackUrl (ที่อยู่รับผล) → ได้ attempt id + ลิงก์ทำข้อสอบ (launchUrl) กลับมา

สำคัญ: Empeo ต้องบันทึก attempt id (รหัสประจำการสอบครั้งนั้น) ผูกกับพนักงานลง DB ทันที — ผลสอบที่ส่งกลับมาในขั้น 3 จะอ้างอิงด้วย id นี้
พนักงาน (Browser) → Exam Server
พนักงานทำข้อสอบ

Empeo ส่งลิงก์ให้พนักงาน (อีเมล / ปุ่มในระบบ) → พนักงานเปิดลิงก์ ทำข้อสอบจนจบ → ระบบข้อสอบตรวจคะแนนและเก็บผลใน database ของตัวเอง — ขั้นนี้ Empeo ไม่ต้องทำอะไรเลย

Exam Server → Empeo Server
ระบบข้อสอบส่งผลกลับมาให้เอง (Webhook)

ทันทีที่สอบเสร็จ ระบบจะ POST ผลสอบ (JSON) ไปที่ callbackUrl ที่ Empeo บอกไว้ในขั้น 1 พร้อมลายเซ็นดิจิทัล (HMAC) ให้ตรวจสอบว่า มาจากระบบข้อสอบจริง → Empeo ตรวจลายเซ็น → บันทึกผลลง DB → ตอบ 200

ถ้า webhook ส่งไม่ถึง (เช่น server ของ Empeo ล่มชั่วคราว) ระบบจะส่งซ้ำให้เองสูงสุด 5 ครั้ง และยังมีช่องทางตามเก็บผลทีหลังเป็นแผนสำรอง — ดูหัวข้อ 8

5. API Reference — English Engine

Base path: <BASE_URL>/english/api · ทุก endpoint ด้านล่างต้องแนบ X-API-Key · Swagger ฉบับเต็ม: <BASE_URL>/english/api/docs

POST /english/api/sessions X-API-Key สร้างการสอบ + ขอลิงก์ทำข้อสอบ

Request

{
  "paperId": "41bf2991-bc9e-453b-bb33-53e11b4a99f7",    // ชุดข้อสอบ (required) — มี 2 ชุด: เต็ม 50 นาที / สั้น 15 นาที · id ของแต่ละชุด ถามภูริ
  "sourceSystem": "empeo",                               // optional แต่ควรส่งเสมอ
  "externalUserId": "emp-001",                           // employee id ของ Empeo
  "email": "somchai@company.co.th",                     // optional
  "displayName": "สมชาย ใจดี",                           // optional
  "callbackUrl": "https://empeo.example.com/api/webhooks/exam-results",  // ที่อยู่รับผล (แนะนำให้ส่ง)
  "timeLimitMin": 50                                     // optional — ไม่ส่งจะใช้ค่าของชุดข้อสอบ (เต็ม 50 / สั้น 15 นาที)
}

Response 201

{
  "attempt": {
    "id": "36930888-b8c8-48f6-9400-ca05d0c59a6f",      // ★ attempt id — Empeo ต้องเก็บค่านี้
    "paperId": "41bf2991-...",
    "subjectId": "c1a2...",
    "sourceSystem": "empeo",
    "externalUserId": "emp-001",
    "status": "pending",
    "timeLimitMin": 50,
    "expiresAt": null                                   // ยังเป็น null ตอนนี้ — จะถูกตั้งเมื่อพนักงานเปิดลิงก์ทำข้อสอบ (เวลาสอบเริ่มนับ) · ตอนนี้ให้ดู launchTokenExpiresAt แทน
  },
  "launchToken": "<single-use token>",                  // ใช้ได้ครั้งเดียว หมดอายุใน 30 นาที
  "launchTokenExpiresAt": "2026-06-03T11:00:00.000Z",
  "launchUrl": "<BASE_URL>/english/exam?t=..."           // ★ ส่งลิงก์นี้ให้พนักงานเปิด
}

object attempt ยังมี field คะแนนติดมาด้วย (correctTotal, maxTotal, cefrLevel, cefrLabel, result, startedAt, completedAt) — ตอนนี้เป็น null ทั้งหมด จะมีค่าเมื่อสอบเสร็จ ไม่ต้องสนใจตอนสร้าง session

Errors: 400 {"error":"paperId is required"} · 401 key ผิด/ไม่ส่ง · 404 ไม่พบ paper

GET /english/api/subjects/{sourceSystem}/{externalUserId}/results X-API-Key ประวัติผลสอบของพนักงานหนึ่งคน

เช่น GET /english/api/subjects/empeo/emp-001/results — คืน {"results": [attempt, ...]} เฉพาะที่สอบเสร็จแล้ว (status: "completed") เรียงใหม่→เก่า (attempt แต่ละตัวมี correctTotal, cefrLevel, result ครบ)

POST /english/api/attempts/{id}/view-link X-API-Key ขอลิงก์หน้าผลสอบ (อายุ 15 นาที) 
// body ว่าง → Response 201:
{
  "attemptId": "36930888-...",
  "viewUrl": "<BASE_URL>/english/result?view_token=...",   // เปิดดูผลแบบอ่านอย่างเดียว
  "expiresAt": "2026-06-03T11:15:00.000Z"
}

404 ถ้าการสอบนั้นยังไม่เสร็จ · มีอีกแบบที่ใช้แค่รหัสพนักงาน (ไม่ต้องรู้ attempt id) ระบบจะหยิบผลล่าสุดให้เอง: POST /english/api/subjects/{sourceSystem}/{externalUserId}/view-link

GET /english/api/attempts?limit=50 X-API-Key รายการ attempt ล่าสุดทั้งหมด

limit default 50, สูงสุด 200 — เอาไว้ทำหน้า dashboard หรือไล่ตรวจสถานะย้อนหลังทีละหลายรายการ

POST /english/api/attempts/{id}/redeliver X-API-Key สั่งส่ง webhook ผลสอบซ้ำ

body ว่าง → คืน {"delivered": true|false} — ใช้เมื่อ Empeo พลาดรับ webhook รอบแรก (เช่น endpoint ล่มอยู่พอดี)

7. Webhook — การรับผลสอบ (สำคัญที่สุด)

นี่คือสิ่งเดียวที่ Empeo ต้อง "สร้างใหม่": endpoint 1 ตัว (หรือ 2 ตัวแยกตามชนิดข้อสอบ) ไว้รอรับผลสอบ — เมื่อพนักงานสอบเสร็จ ระบบข้อสอบจะ POST ผลมาที่ callbackUrl ที่ Empeo แนบไว้ตอนสั่งเปิดสอบ

7.1 Headers ที่ส่งมาด้วยทุกครั้ง

POST <callbackUrl ของ Empeo>
Content-Type: application/json
X-Signature: sha256=<HMAC-SHA256(body ดิบ, PARENT_API_KEY) เป็น hex ตัวพิมพ์เล็ก>
X-Attempt-Id: <attempt id>

7.2 Payload — English (ส่งเมื่อสอบเสร็จ — status: "completed")

{
  "attemptId": "36930888-b8c8-48f6-9400-ca05d0c59a6f",
  "paperId": "41bf2991-...",
  "subjectId": "c1a2...",
  "sourceSystem": "empeo",
  "externalUserId": "emp-001",
  "status": "completed",
  "completedAt": "2026-06-03T10:15:00.000Z",
  "correctTotal": 38,           // ★ คะแนนรวม (ดิบ)
  "maxTotal": 50,              // ★ คะแนนเต็ม (ชุดเต็ม 50 / ชุดสั้น 20)
  "cefrLevel": 4,              // ★ band ระดับ (ตัวเลข — ดูตารางใต้ตัวอย่าง)
  "cefrLabel": "Advanced",    // ป้ายชื่อระดับ — ตรงกับที่แสดงบนหน้าผลสอบ
  "result": {
    "parts": [                  // คะแนนแยกรายพาร์ท (7 พาร์ท)
      { "id": 1, "title": "Photographs", "section": "Listening", "correct": 5, "total": 6 },
      // ... พาร์ท 2-7 ...
    ],
    "skills": {                 // คะแนนแยกรายทักษะ
      "listening":  { "correct": 20, "total": 25 },
      "vocabulary": { "correct": 6,  "total": 8 },
      "grammar":    { "correct": 5,  "total": 7 },
      "reading":    { "correct": 7,  "total": 10 },
      "total":      { "correct": 38, "total": 50 }
    }
  },
  "engineVersion": "1.0"
}

แนะนำให้แยก correctTotal / maxTotal / cefrLevel / cefrLabel เก็บเป็นคอลัมน์ของตัวเอง ส่วน result เก็บทั้งก้อนเป็น JSON ไว้ใช้แสดงคะแนนแยกละเอียด

เกณฑ์ตัดระดับ (cefrLevel / cefrLabel) ขึ้นกับชุดข้อสอบ — ชุดเต็ม 50 ข้อ: 0–15 = 1 Novice · 16–24 = 2 Beginner · 25–33 = 3 Intermediate · 34–41 = 4 Advanced · 42–50 = 5 Expert · ชุดสั้น 20 ข้อ: 0–6 = 1 Beginner · 7–15 = 2 Intermediate · 16–20 = 3 Advanced (เกณฑ์ทั้งคู่คิดจากคะแนนดิบ correctTotal · cefrLabel ตรงกับที่แสดงบนหน้าผลสอบของพนักงาน)

7.3 Payload — MBTI (ส่งเมื่อสอบเสร็จ — status: "completed")

{
  "attemptId": "3c9f04ae-39dc-4e22-9bb1-c1224d7e9222",
  "subjectId": "a7b3...",
  "sourceSystem": "empeo",
  "externalUserId": "emp-001",
  "status": "completed",
  "completedAt": "2026-06-03T10:20:00.000Z",
  "result": {
    "code": "ISTJ",             // ★ MBTI code
    "softCode": "I · S · T · J", // แกนที่ก้ำกึ่งจะแสดงเป็น เช่น "E/I"
    "axes": {                   // รายละเอียดรายแกน EI / SN / TF / JP
      "EI": { "winner": "I", "leftPercent": 35, "rightPercent": 65,
              "dominantPercent": 65, "confidence": "clear", "isMidzone": false }
      // "SN", "TF", "JP" โครงเดียวกัน
    },
    "bars":       { "EI": 35, "SN": 60, "TF": 70, "JP": 75, "ES": 35 },  // ES เป็น alias ของ EI — ไม่ต้องใช้

7.4 กติกา 3 ข้อที่ endpoint ฝั่ง Empeo ต้องทำ

① ตรวจลายเซ็นก่อนเชื่อข้อมูล — คำนวณ HMAC-SHA256 จาก body ดิบ (ก่อนแปลงเป็น JSON) ด้วย PARENT_API_KEY แล้วเทียบกับค่าใน header X-Signature ด้วยฟังก์ชันเทียบแบบ timing-safe (กันการเดา key จากเวลาตอบ):

// C# / .NET
[HttpPost("api/webhooks/exam-results")]
public async Task<IActionResult> Receive()
{
    using var reader = new StreamReader(Request.Body);
    var rawBody = await reader.ReadToEndAsync();              // ← ต้องเป็น body ดิบ ก่อนแปลง JSON

    var key = Encoding.UTF8.GetBytes(_config["ParentApiKey"]);
    using var hmac = new HMACSHA256(key);
    var expected = "sha256=" + Convert.ToHexString(
        hmac.ComputeHash(Encoding.UTF8.GetBytes(rawBody))).ToLowerInvariant();

    var received = Request.Headers["X-Signature"].ToString();
    if (!CryptographicOperations.FixedTimeEquals(
            Encoding.UTF8.GetBytes(expected), Encoding.UTF8.GetBytes(received)))
        return Unauthorized();

    var payload = JsonSerializer.Deserialize<JsonElement>(rawBody);
    // ② บันทึกลง DB ด้วย attempt id (upsert) ... ③ ตอบ 200 ให้เร็ว
    return Ok();
}
// Node.js / Express (เผื่อใช้ทดสอบ)
app.post('/api/webhooks/exam-results',
  express.raw({ type: 'application/json' }),       // ← ต้องได้ body ดิบ
  (req, res) => {
    const expected = 'sha256=' + crypto.createHmac('sha256', PARENT_API_KEY)
                                       .update(req.body).digest('hex');
    const ok = crypto.timingSafeEqual(Buffer.from(expected),
                                      Buffer.from(req.headers['x-signature'] || ''));
    if (!ok) return res.status(401).end();
    const payload = JSON.parse(req.body);
    // upsert แล้วตอบ
    res.status(200).end();
  });

② บันทึกแบบ upsert ด้วย attempt id (มีแล้วอัปเดตทับ ยังไม่มีค่อยสร้างใหม่)
ถ้าระบบข้อสอบไม่ได้รับคำตอบ 2xx จะส่งซ้ำให้สูงสุด 5 ครั้ง — แปลว่า Empeo อาจได้รับผลชุดเดิมซ้ำหลายรอบ ดังนั้น endpoint ต้องรับข้อมูลซ้ำได้โดยผลใน DB ไม่เพี้ยน (idempotent) ไม่ใช่ insert แถวใหม่ทุกครั้งที่มีของเข้ามา

③ ตอบ 2xx ให้เร็ว
ฝั่งผู้ส่งรอคำตอบแค่ 8 วินาที — บันทึกลง DB แล้วตอบ 200 ทันที งานที่ใช้เวลานาน (ส่งแจ้งเตือน, ประมวลผลต่อ) ให้แยกไปทำเบื้องหลังทีหลัง

Backend ของ Empeo ขอลิงก์ ณ ตอนนั้นเลย

11. Checklist ฝั่ง Empeo

  • เก็บ mapping ใน DB: ตาราง/คอลัมน์เก็บ attemptId ผูกกับ employee + ชนิดข้อสอบ ตั้งแต่ตอนสร้าง session และคอลัมน์ผลสอบ (English: คะแนน + CEFR · MBTI: code) + JSON เต็ม
  • Webhook endpoint 1 ตัว: รับ POST → ตรวจลายเซ็น X-Signature (HMAC จาก body ดิบ) → บันทึกแบบ upsert ด้วย attempt id → ตอบ 200 ให้เร็ว (โค้ดตัวอย่างอยู่หัวข้อ 7.4)
  • เก็บ PARENT_API_KEY ฝั่ง server เท่านั้น (config/secret store) — ใช้ทั้งตอนเรียก API และตอนตรวจลายเซ็น ห้ามอยู่ใน frontend
  • (แนะนำ) งานเก็บตกอัตโนมัติ: ตรวจการสอบที่เปิดไว้นานแต่ยังไม่มีผล แล้วดึงผล (pull) หรือสั่งส่งซ้ำ (redeliver) — กันผลตกหล่น

3 อย่างนี้ ถามภูริ: Base URL ของแต่ละ environment · PARENT_API_KEY ของแต่ละ environment (ส่งผ่านช่องทางปลอดภัย) · paperId ของชุดข้อสอบ English ที่ใช้งาน

0. TL;DR — Empeo ต้องทำอะไรบ้าง

ระบบเป็น 1 container มี gateway (:3000) แยก path ให้ 2 engine ใช้ DB เดียวกัน — /english/* และ /mbti/*. Empeo คุยแบบ server-to-server ไม่ยุ่งกับหน้าเว็บข้อสอบ:

  1. POST สร้างการสอบ → เก็บ attemptId + ส่ง launchUrl ให้พนักงาน
  2. พนักงานเปิดลิงก์ทำข้อสอบ → ระบบ score + เก็บผลเอง (Empeo ไม่ต้องทำอะไร)
  3. สร้าง webhook endpoint 1 ตัว รอรับผล → verify ลายเซ็น → upsert → ตอบ 2xx

โค้ด business logic จริง: English apps/english/server/src/routes/attempts.js + webhook.js · MBTI apps/mbti/server/app.js + assessmentService.js + webhook.js

1. กติกาที่ใช้ร่วมกันทั้ง 2 engine

1.1 Authentication

ทุก endpoint ฝั่ง parent ใช้ header เดียวกัน — key เดียวใช้ทั้งสอง engine และเป็น secret เดียวกับที่ใช้ sign/verify webhook:

X-API-Key: <PARENT_API_KEY>

English เช็คใน requireParentAuth (middleware/parentAuth.js) · MBTI เช็คใน requireParentService app.js:194-208 — เทียบแบบ constant-time, ผิด/ไม่ส่ง → 401

หมายเหตุ MBTI: endpoint /complete (พนักงาน submit คำตอบ) ใช้ Bearer attempt token ไม่ใช่ X-API-Key — แต่ตัวนี้ browser เป็นคนเรียก ไม่ใช่ Empeo app.js:84-97, 210-215

1.2 Identity — คู่ (sourceSystem, externalUserId)

ระบุพนักงานด้วย 2 ค่านี้ ส่งค่าเดิมเสมอทั้ง English และ MBTI → upsert ลงตาราง shared.subjects (1 แถวต่อ 1 คน ใช้ร่วมทั้งสอง engine):

  • English: prisma.subject.upsert attempts.js:159-173
  • MBTI: prisma.assessmentSubject.upsert assessmentService.js:20-37

upsert จะเก็บ snapshot ล่าสุดของ email/displayName โดยไม่ทับด้วย null

หลักการ: ทุก field ที่ Empeo เห็น (request / response / webhook) เป็น camelCase สถานะตอนเสร็จบน wire = "completed" เสมอ — แต่กลไกข้างในต่างกัน:

4. Verify ลายเซ็น + กติกาฝั่ง Empeo

4.1 Headers ที่ส่งมาทุกครั้ง

English webhook.js:85-90 · MBTI webhook.js:82-86 — เหมือนกันเป๊ะ

Content-Type: application/json
X-Signature: sha256=<hex>     // HMAC-SHA256(rawBody, PARENT_API_KEY), lowercase hex
X-Attempt-Id: <attempt id>

วิธี sign ในโค้ด (เหมือนกันทั้งสอง): 'sha256=' + createHmac('sha256', secret).update(body).digest('hex') โดย body = JSON.stringify(payload) — ต้อง HMAC จาก body ดิบตัวเดียวกัน

4.2 กติกา 3 ข้อที่ endpoint ฝั่ง Empeo ต้องทำ

① Verify ก่อนเชื่อ — HMAC จาก raw body (ก่อน parse JSON) เทียบแบบ timing-safe:

// Node.js / Express
app.post('/api/webhooks/exam-results',
  express.raw({ type: 'application/json' }),        // ← ต้องได้ body ดิบ
  (req, res) => {
    const expected = 'sha256=' + crypto.createHmac('sha256', PARENT_API_KEY)
                                       .update(req.body).digest('hex');
    const ok = crypto.timingSafeEqual(Buffer.from(expected),
                 Buffer.from(req.headers['x-signature'] || ''));
    if (!ok) return res.status(401).end();
    const payload = JSON.parse(req.body);
    // ② upsert ด้วย payload.attemptId ... ③ ตอบ 200 ให้เร็ว
    res.status(200).end();
  });
// C# / .NET — verify เหมือนกัน
var key = Encoding.UTF8.GetBytes(parentApiKey);
using var hmac = new HMACSHA256(key);
var expected = "sha256=" + Convert.ToHexString(
    hmac.ComputeHash(Encoding.UTF8.GetBytes(rawBody))).ToLowerInvariant();
if (!CryptographicOperations.FixedTimeEquals(
        Encoding.UTF8.GetBytes(expected),
        Encoding.UTF8.GetBytes(receivedSignature)))
    return Unauthorized();

② Upsert ด้วย attemptId (idempotent) — retry สูงสุด 5 ครั้ง (English WEBHOOK_MAX_ATTEMPTS webhook.js:7,43 · MBTI config.webhookMaxAttempts webhook.js:42) → อาจได้ payload เดิมซ้ำ ห้าม insert แถวใหม่ทุกรอบ

③ ตอบ 2xx ภายใน 8 วินาที (WEBHOOK_TIMEOUT_MS default 8000 — English webhook.js:6 · MBTI config.webhookTimeoutMs webhook.js:74) งานหนักให้แยกไปทำ background

สำเร็จแล้วระบบ stamp result_delivered_at / resultDeliveredAt กันส่งซ้ำ (English webhook.js:42,121 · MBTI webhook.js:41,113)

9. Checklist ฝั่ง Empeo + ของที่ต้องถาม

  • DB mapping: เก็บ attemptId + engine + employee ตั้งแต่สร้าง session และคอลัมน์ผล (English: correctTotal/cefr · MBTI: code) + เก็บ result ทั้งก้อนเป็น JSON
  • Webhook endpoint 1 ตัว: รับ raw body → verify X-Signature → upsert ด้วย attemptId → ตอบ 2xx เร็ว
  • PARENT_API_KEY ฝั่ง server เท่านั้น — ใช้ทั้งเรียก API และ verify webhook ห้ามอยู่ใน frontend
  • (แนะนำ) cron เก็บตก: ไล่การสอบที่ยังไม่มีผล → pull / redeliver
ของที่ต้องถามภูริ: Base URL แต่ละ environment · PARENT_API_KEY แต่ละ environment (ส่งผ่านช่องทางปลอดภัย) · paperId ของชุดข้อสอบ English (full / short)
